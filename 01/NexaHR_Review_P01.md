## Proposals — only in `Mode: defects + elevation`, max 6, ranked
1. **"چرا فلانی وارد نمی‌شود؟" — یک صفحه برای HR.** Today a lockout reaches HR as a one-off notification and the remedy (`POST /api/users/{id}/unlock`) exists, but HR cannot see *currently locked accounts* without spelunking the audit log. User-visible outcome: HR opens one panel and sees who is locked, until when, and unlocks with one audited click. Change: one read endpoint over `login_attempts` (`locked_until > now`) + a small panel section. Files touched: `users.py`, one schema, one frontend section. Breaks nothing (read-only + existing audited unlock).
2. **Let a forced-password-change user see and revoke their own sessions.** The allowlist (deps.py:17-36) blocks `/api/auth/sessions` and `DELETE /api/auth/sessions/{id}`, so someone compelled to change a password on a possibly-compromised machine cannot cut off a stolen device at the same time. Both endpoints are strictly self-scoped already (auth.py:304-347). Change: add the two paths to the allowlist. Files touched: `api/deps.py` (one line) + tests.
3. **One seat-visibility rule, one function.** Findings 1-4 share a root cause: the "seats this user occupies" predicate is rewritten in five places (scope, personnel columns, role-overview, copilot queue, prompt context) and each copy has already drifted once. Change: a single `seats_of_user(db, user_id) -> ColumnElement` in `services/workflow.py` (next to `may_act_at`), consumed by all five; add a parity test mirroring `test_personnel_visibility_scope.py` for evaluations. Files touched: `evaluations.py`, `personnel.py`, `dashboard.py`, `ai/tools/evaluations.py`, `ai/context.py` + one test file. This is drift-proofing; it does not change any current decision except the bug in finding 1.
4. **Say "suppressed" where a number is suppressed.** In the executive/unit views, `suppressed_avg` returns `null` and the row renders like "no data" — an HR user cannot distinguish "too few people to show" from "nothing happened". User-visible outcome: the chart labels small cohorts "میانگین برای کمتر از ۵ نفر نمایش داده نمی‌شود" instead of a blank. Change: return the cohort count alongside each row (already computed) and let the frontend render the label. Files touched: `analytics.py`/`reports.py` serializers + one frontend tooltip. No change to the suppression rule itself, so no privacy effect; nothing touches snapshots or the signed document.
