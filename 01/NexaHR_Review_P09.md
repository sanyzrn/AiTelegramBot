# P09 — Frontend & a11y (frontend/src/)

Repo: NexaHR @ 27c83e5, mode: defects + elevation. Verification basis: full read of the React app (auth, api, ui, components, pages), byte-level check of suspect lines, oxlint 0/0 on 176 files, `tsc -b && vite build` green, 407/407 vitest green (re-ran focusTrap/Modal suites myself). No backend probe was needed for any finding below; every file:line was read in the current checkout. Note: my tool output strips ANSI-like byte pairs (`[h`, `[m`, `[i`, …) — one suspect "malformed selector" in `focusTrap.ts` turned out to be an output artifact, disproven by extracting the string with a regex; the selector is a valid `a[href], …`.

## Verdict — 3 lines
The boundaries this angle targets hold up: token stays in memory, login *and* logout clear the React Query cache, drafts/copilot state die with the session, PermissionsContext is fail-closed with three refetch triggers, and every module key the UI gates on exists server-side — no cross-user leak path survived inspection.
Four Low findings, all interface-level: five form fields still lack the length guards the repo's own open list already tracks; one Escape press closes every stacked overlay at once; five sub-24px buttons escape the tap-target test's regex; the users-page personnel picker silently caps at 1000.
No Medium/High, no REGRESSIONs of the ALREADY-FIXED list; lint/build/407 tests green.

## Verified correct
- **Cross-user cache boundaries on shared machines (the angle's #1).** Access token lives in module memory only (`api/client.ts:6-13`), refresh is an HttpOnly cookie; `login()` *and* `logout()` both `queryClient.clear()` (`auth/AuthContext.tsx:54, 74`) — so the second user on the same tab can never render the first user's rows even for a frame; logout additionally deletes every `nexahr:draft:` localStorage key (`ui/useLocalDraft.ts:20-33`) and all SW caches (`pwa.ts:14-22`); a failed 401-refresh falls through to a *full-page* redirect (`client.ts:75-84`), which by construction wipes all in-memory state; copilot conversation state is React-context memory only, mounted inside the Layout shell that returns `null` when logged out (`components/copilot/CopilotSession.tsx:40-71`, `Layout.tsx:82`). localStorage holds nothing but theme, sidebar-collapse, and prefixed drafts; there is no persist plugin on the QueryClient. Retry policy never re-sends 4xx (main.tsx:28-32) — no double-charged rate-limited failures.
- **PermissionsContext fail-closed module gating (the angle's #2).** `isModuleEnabled` defaults to `false` when data is missing or the fetch errored (`auth/PermissionsContext.tsx:58-63`), gated UIs additionally require `!permissionsLoading` (`pages/employee/MyEvaluationsPage.tsx:326-343`); the query is keyed with the user id, enabled only when logged in, refreshed on window focus, every 5 minutes, and on *any* 403 from any endpoint (:66-95) — the repo's own open item «مجوزها هیچ‌وقت تازه نمی‌شوند» is verified closed; `ProtectedRoute` waits for pending permissions instead of wrongly denying capability routes (`ProtectedRoute.tsx:45-47`). Every module key the UI gates on (`periods`, `improvement_plans`, `self_assessment`, `objections`, `employee_evaluation_visibility`, `employee_overview_cards`, `employee_result_acknowledgement`, `role_analytics`) exists in `backend/app/core/modules.py` — zero dead keys, and the server keeps the real enforcement (`ensure_module_enabled` at 8 write/read sites), so UI gating is cover only, as designed.
- **Focus traps and keyboard paths.** `useFocusTrap` is valid and sound: the focusable selector is a correct `a[href], button, textarea, input, select, [tabindex]:not([tabindex="-1"])` (byte-verified — see header note), traps Tab/Shift+Tab, restores focus on close, reads `onEscape` through a ref so parent re-renders don't steal focus (focusTrap.ts:22-84). `Modal` renders via portal with `aria-modal` + `aria-labelledby` that works for ReactNode titles (Modal.tsx:93-100), non-dismissible variant drops Escape entirely; the mobile drawer gets the same trap with `role="dialog"` (Layout.tsx:61-68, 157-180); skip-link to `#main-content` (Layout.tsx:124-129); the forced-password state renders a bare shell so navigation/notifications/copilot are *not rendered at all*, stronger than a scrim (Layout.tsx:84-106). JalaliDatePicker: capture-phase Escape arbitration, roving-tabindex day grid with arrow-key handling, focus return — its three dedicated test files pass. PersonPicker implements the full combobox pattern incl. `aria-activedescendant` (PersonPicker.tsx:58-63, 184) — the repo's open item verified closed. NotificationBell closes on Escape and returns focus to the bell (NotificationBell.tsx:33-37); Toast announcements use `role="alert"`.
- **Form validation vs server rules.** Password: client required rules (≥10, not-username) match the server (`utils/password.ts` vs `backend/app/api/routers/auth.py:271`; generator uses `crypto.getRandomValues` with Fisher–Yates and an ambiguity-free alphabet). Text limits are mirrored (`utils/textLimits.ts`) and value-locked by `test_text_limits.py`; the applied fields all carry `maxLength`+`CharCounter` (comments, replies, evaluator comment, objection, return/cancel/recovery/deadline reasons, bonus reason, evidence). The scoring form validates against the record's **stamped** `scoring_rules`, not today's active scheme (`EvaluationDetailPage.tsx:74-78`) — mid-cycle scheme activation cannot drift form rules vs server (P03's pair, holds); score entry 1..5 is button-driven matching `ScoreInput(ge=1, le=5)`; evidence-required scores and min-word count come from the same stamped config; special score validates 0..scheme-cap + Persian-numeral parsing (`toMachineNumber`, five tests) matching `SpecialScoreUpdate(ge=0, le=100)`; `UsersPage.tsx:80` enforces employee→personnel exactly like `UserCreate`'s validator.
- **Error and empty states.** Every list surface I opened has the trio: inline error line (`EvaluationList.tsx:339-341`), skeletons while pending (:346-352), `EmptyState` (:355) + pagination — same pattern in Personnel/Users/AuditLog/Reports/dashboards/Sessions/detail pages, which use `retry:false` so 403/404 surface immediately; `PersonScorecard` has explicit empty states for no-selection and no-result. `ErrorBoundary` renders a reload CTA (ErrorBoundary.tsx:54-59) and is re-keyed per pathname so a stale error state cannot survive navigation (Layout.tsx:232).
- **Touch targets & contrast (both themes).** The 24px `.tap-target` rule itself is test-locked down to its CSS values, including that `display:inline-flex` survives (tapTarget.test.ts); contrast tests compute real WCAG ratios — `--color-gray-400` ≥4.5:1 on white and `#f9fafb` in light theme and on `#1b2031` in dark (lightThemeContrast.test.ts), with Tailwind 4 mapping `gray-*` to those redefined tokens so all components follow; `theme-init.js` applies theme pre-paint.
- **PWA/service-worker cache.** `public/sw.js` never caches `/api/` or `/verify/` (`isNeverCached`), navigation is network-first with the cached shell only as offline fallback, and the offline fallback for `/verify/` is an honest 503 page rather than a cached document (`offlineResponse`); hashed `/assets/*` are cache-first under a versioned cache, `activate` prunes any older version, `skipWaiting`+`clients.claim`+one guarded `controllerchange` reload prevent mixed-version runs; registration is PROD-only and failure is silent-by-design; a mid-session deploy ends at the ErrorBoundary card whose reload fetches the fresh shell — degraded but always recoverable. The AuthContext comment's claim that SW caches hold no user data is true (only `/`, manifest, one icon are precached).

## Proposals — only in `Mode: defects + elevation`, max 6, ranked
1. **«کدام فیلد؟» — خطا زیرِ خودِ فیلد بنشیند.** HR cannot tell *which* input a 422 refers to today (backend already returns structured `detail_items` with field names, explicitly "تا UI بتواند خطا را کنار خودِ فیلد نشان دهد" — validation_errors.py:117-122, unused by the client). Outcome: an employee with one over-long note fixes it in seconds instead of hunting 20 fields; same for the indicator/goal forms. Change: surface `detail_items` through `extractErrorMessage` consumers and render the message next to the matching field in the 3-4 forms that own those fields. Cost: ~4 files, no backend change.
2. **آفلاین باید «آفلاین» بگوید.** The SW promises «پوستهٔ برنامه باز می‌شود و می‌گوید آفلاین» (sw.js header) but nothing in the app ever says it: offline, every query surfaces the generic «خطایی غیرمنتظره رخ داد» toast. Outcome: the supervisor on the plant floor (the stated PWA motivation) understands why nothing loads instead of distrusting the system. Change: one `navigator.onLine` + online/offline listener banner with a retry hint, mounted in Layout. Cost: 2 files.
3. **هزار نفر صدمین: انتخابگرِ سمتِ سرور برای پیوندِ حساب.** An org past 1000 personnel cannot link employee accounts at all (finding 4), and the select will also strain before that. Outcome: HR can link any employee however large the roster grows, with the same keyboard/a11y behavior as the rest of the app. Change: reuse `PersonPicker` for the personnel_id field. Cost: 1 file (component exists).
4. **هر Escape یک لایه.** Closing the calendar, a confirm dialog, or the copilot window must never throw away the half-filled form behind it (finding 2). Outcome: keyboard users stop losing work to a key that means "dismiss this", not "dismiss everything". Change: a layer stack / capture-phase arbitration inside `useFocusTrap` so only the topmost layer answers Escape; `Modal`/`Copilot`/drawer call sites untouched. Cost: ~2 files incl. a stacked-overlay test mirroring `JalaliDatePicker.escape.test.tsx`.
5. **استقرارِ تازه، نیم‌باز را خودش ترمیم کند.** After a deploy, the first click on a never-yet-loaded page of a long-open tab lands on a 404 chunk and shows the error card. Outcome: the app reloads itself once instead of teaching the user to press F5. Change: handle Vite's `vite:preloadError` (or wrap the lazy imports) with a single guarded `location.reload()`, reusing the existing `refreshing`-flag pattern from pwa.ts. Cost: 2 files.
6. **قاعدهٔ ۲۴ پیکسل بی‌استثنا.** The tap-target test's regex misses every sub-24px button that doesn't use `text-xs` (finding 3). Outcome: the next tiny button fails CI instead of reaching a motor-impaired user. Change: widen the rule to `text-sm` and icon-only buttons; fix the five current offenders in the same commit. Cost: 2 files (test + the five class additions).
